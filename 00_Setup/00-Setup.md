# Pipeline Environment Setup Guide

> **Different tools need different environments.**
> You do not need everything running before you start.
> This guide maps each tool to the right setup option and tells you exactly what to provision.

---

## Environment Options at a Glance

| Option                    | Cost                                | Best For                                    | Persistent?     | Setup Time  |
| ---------------------------| -------------------------------------| ---------------------------------------------| -----------------| -------------|
| **A — Local machine**     | Free                                | Trivy, Checkov (no server needed)           | Yes             | 5 min       |
| **B — AWS EC2 t3a.large** | ~$0.08/hr, stop when not practicing | Tools 01–09, full Docker Compose stack      | Per session     | 10 min once |

## Option A — Local Machine (Start Here — Tools 03 and 04)

Zero infrastructure. Do this today.

### Install Trivy (Windows — WSL or PowerShell)

**Option 1 — WSL (recommended):**
```bash
sudo apt-get install wget apt-transport-https gnupg lsb-release
wget -qO - https://aquasecurity.github.io/trivy-repo/deb/public.key | sudo apt-key add -
echo "deb https://aquasecurity.github.io/trivy-repo/deb $(lsb_release -sc) main" \
  | sudo tee /etc/apt/sources.list.d/trivy.list
sudo apt-get update && sudo apt-get install -y trivy
trivy --version
```

**Option 2 — Docker (no install at all):**
```bash
docker run --rm aquasec/trivy image nginx:latest
```

**First thing to run:**
```bash
# Scan any public image — see what real output looks like
trivy image nginx:latest
trivy image ubuntu:22.04
trivy image alpine:3.19

# Compare the finding counts — this is your first triage exercise
```

### Install Checkov (Windows — PowerShell or WSL)

```powershell
pip install checkov
checkov --version
```

**First thing to run — on your own files:**
```bash
# Point it at your existing Terraform (from K8s infra or Ansible infra)
checkov -d "C:\Users\akshat.b.verma\OneDrive - Accenture\Desktop\My-Devops\Ansible\Infra\terraform"

# Or K8s manifests you already wrote
checkov -d "C:\Users\akshat.b.verma\OneDrive - Accenture\Desktop\My-Devops\K8s" --framework kubernetes
```

Real output on your own files — not a demo. This is where learning starts.

## Option B — AWS EC2 (Recommended for Tools 01–05, 07, 09)

Single EC2 instance running Docker Compose for Jenkins + SonarQube + Nexus.

**Instance size:**
- `t3a.large` (2 vCPU, 8GB) — minimum, works fine if you run tools one at a time
- `t3.xlarge` (4 vCPU, 16GB) — comfortable, run everything simultaneously
- **Do NOT use t3.medium** — SonarQube alone needs 3GB, the machine will OOM constantly

### Step 1 — Terraform to Provision the Instance

Create a folder `Pipeline/infra/` and put these files in it:

```hcl
# Pipeline/infra/main.tf
# Generated by GitHub Copilot
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = var.region
}

data "aws_ami" "ubuntu" {
  most_recent = true
  owners      = ["099720109477"]  # Canonical
  filter {
    name   = "name"
    values = ["ubuntu/images/hvm-ssd/ubuntu-jammy-22.04-amd64-server-*"]
  }
}

resource "aws_security_group" "cicd" {
  name        = "cicd-sg"
  description = "CI/CD tools access"

  ingress {
    description = "SSH"
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = [var.my_ip]   # restrict SSH to your IP only
  }

  ingress {
    description = "Jenkins"
    from_port   = 8080
    to_port     = 8080
    protocol    = "tcp"
    cidr_blocks = [var.my_ip]
  }

  ingress {
    description = "SonarQube"
    from_port   = 9000
    to_port     = 9000
    protocol    = "tcp"
    cidr_blocks = [var.my_ip]
  }

  ingress {
    description = "Nexus UI"
    from_port   = 8081
    to_port     = 8081
    protocol    = "tcp"
    cidr_blocks = [var.my_ip]
  }

  ingress {
    description = "Nexus Docker repo"
    from_port   = 8082
    to_port     = 8082
    protocol    = "tcp"
    cidr_blocks = [var.my_ip]
  }

  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

resource "aws_instance" "cicd" {
  ami                    = data.aws_ami.ubuntu.id
  instance_type          = var.instance_type
  key_name               = var.key_name
  vpc_security_group_ids = [aws_security_group.cicd.id]

  root_block_device {
    volume_size = 30   # SonarQube + Nexus need disk space for data
    volume_type = "gp3"
  }

  user_data = file("${path.module}/setup.sh")

  tags = {
    Name = "cicd-pipeline-lab"
  }
}

output "instance_ip" {
  value       = aws_instance.cicd.public_ip
  description = "SSH and browser access: ssh ubuntu@<this-ip>"
}

output "jenkins_url"    { value = "http://${aws_instance.cicd.public_ip}:8080" }
output "sonarqube_url"  { value = "http://${aws_instance.cicd.public_ip}:9000" }
output "nexus_url"      { value = "http://${aws_instance.cicd.public_ip}:8081" }
```

```hcl
# Pipeline/infra/variables.tf
# Generated by GitHub Copilot
variable "region"        { default = "ap-south-1" }
variable "instance_type" { default = "t3a.large" }
variable "key_name"      { description = "Name of your AWS key pair" }
variable "my_ip"         {
  description = "Your public IP in CIDR format — get it from https://checkip.amazonaws.com"
  # Example: "103.x.x.x/32"
}
```

```bash
# Pipeline/infra/setup.sh
# Runs on the EC2 instance at first boot
#!/bin/bash
set -e

apt-get update -y
apt-get install -y docker.io docker-compose-plugin git curl python3-pip unzip

# Add ubuntu user to docker group
usermod -aG docker ubuntu

# SonarQube + Elasticsearch requirement
sysctl -w vm.max_map_count=524288
sysctl -w fs.file-max=131072
echo "vm.max_map_count=524288" >> /etc/sysctl.conf
echo "fs.file-max=131072" >> /etc/sysctl.conf

# Install Trivy
apt-get install -y wget apt-transport-https gnupg lsb-release
wget -qO - https://aquasecurity.github.io/trivy-repo/deb/public.key | apt-key add -
echo "deb https://aquasecurity.github.io/trivy-repo/deb $(lsb_release -sc) main" \
  >> /etc/apt/sources.list.d/trivy.list
apt-get update && apt-get install -y trivy

# Install Checkov
pip3 install checkov

# Install Cosign
COSIGN_VERSION=$(curl -s https://api.github.com/repos/sigstore/cosign/releases/latest \
  | grep tag_name | cut -d '"' -f 4)
curl -Lo /usr/local/bin/cosign \
  "https://github.com/sigstore/cosign/releases/download/${COSIGN_VERSION}/cosign-linux-amd64"
chmod +x /usr/local/bin/cosign

echo "Setup complete" >> /tmp/setup-done.txt
```

### Step 2 — Provision

```bash
cd Pipeline/infra/
terraform init
terraform apply -var="key_name=your-key-name" -var="my_ip=YOUR.IP.HERE/32"

# After apply completes:
# Outputs show the IP and URLs
# Wait 3-4 minutes for user_data (setup.sh) to finish running
```

### Step 3 — Verify the EC2 is Ready

```bash
ssh ubuntu@<instance_ip>
trivy --version          # should print version
checkov --version        # should print version
docker --version         # should print version
cat /tmp/setup-done.txt  # confirms setup.sh finished
```

### Step 4 — Start the CI/CD Stack

Copy the Docker Compose from `10_Full_Pipeline_Project/tasks.md` to the EC2 instance, then:

```bash
docker compose up -d
docker compose ps      # all services should be Up

# Wait 2-3 minutes for SonarQube to fully start
docker compose logs -f sonarqube   # wait for "SonarQube is up"
docker compose logs -f nexus       # wait for "Started Sonatype Nexus"
```

Access from your Windows browser:
```
http://<instance_ip>:8080   → Jenkins
http://<instance_ip>:9000   → SonarQube  (admin/admin)
http://<instance_ip>:8081   → Nexus      (admin/get password from container)
```

Get Nexus initial password:
```bash
docker exec nexus cat /nexus-data/admin.password
```

Get Jenkins initial password:
```bash
docker exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword
```

### Cost Control — Stop When Not Practicing

```bash
# Stop the instance (no compute charges while stopped — only ~$0.03/day for storage)
aws ec2 stop-instances --instance-ids $(terraform output -raw instance_id)

# Start again next session (same IP changes — check terraform output)
aws ec2 start-instances --instance-ids $(terraform output -raw instance_id)
```

Or use Terraform to destroy completely at end of week:
```bash
terraform destroy   # deletes everything, zero ongoing cost
# Next session: terraform apply again — setup.sh re-runs automatically
```

**Note after restart:** Docker containers are stopped when the instance stops. SSH in and run `docker compose up -d` again after starting the instance.

## Option C — Oracle Free Tier (Preferred if You Want Always-On)

You already have Oracle Free Tier set up for K8s. Use the same account.

**Create a second VM for the CI/CD stack:**

1. OCI Console → Compute → Instances → Create Instance
   - Shape: `VM.Standard.A1.Flex` (ARM — always free)
   - OCPUs: 2 | RAM: 12GB
   - OS: Ubuntu 22.04
   - Add your SSH key
2. Open ports in your VCN Security List: `22, 8080, 8081, 8082, 9000`

SSH in and run the same `setup.sh` content from Option B manually:
```bash
# Copy setup.sh content and run it, or paste and execute each section
bash setup.sh
```

Then run the Docker Compose stack exactly as in Option B Step 4.

**Advantage over AWS:** Always running, no stop/start needed, no cost concern. Good if you want to come back to a running SonarQube with existing projects.

## Daily Workflow Cheatsheet

```bash
# Start your session
aws ec2 start-instances --instance-ids <id>   # if using AWS
ssh ubuntu@<ip>
docker compose up -d
# Wait 2 min, then open Jenkins/SonarQube/Nexus in browser

# End your session
docker compose stop          # preserves data (volumes persist)
aws ec2 stop-instances --instance-ids <id>

# Clean restart (nuke all tool data — fresh start)
docker compose down -v       # -v removes volumes (all SonarQube projects, Nexus repos gone)
docker compose up -d
```

## Port Reference

| Service | URL from Browser | URL from Inside Jenkins Container |
|---------|-----------------|----------------------------------|
| Jenkins | `http://<ip>:8080` | `http://jenkins:8080` |
| SonarQube | `http://<ip>:9000` | `http://sonarqube:9000` |
| Nexus UI | `http://<ip>:8081` | `http://nexus:8081` |
| Nexus Docker | `http://<ip>:8082` | `http://nexus:8082` |

**Important:** When configuring tool URLs inside Jenkins (e.g. SonarQube server URL), use the container name (`http://sonarqube:9000`), NOT the public IP. From inside a Docker container, `localhost` refers to that container itself, not the host machine.
