# 05 — Nexus Repository Manager: Artifact Registry

> The central store for your Docker images, Maven JARs, npm packages, and more.
> Jenkins pushes here. ArgoCD (or K8s) pulls from here.

---

## What It Is + Why It Matters

Nexus (by Sonatype) is a universal artifact repository manager. In your pipeline it serves as the **Docker registry** — after the image passes Trivy scan, Jenkins pushes it to Nexus. ArgoCD then deploys the image from Nexus to K8s.

**Why use Nexus instead of Docker Hub or ECR?**
- **Self-hosted:** You control who can pull your images — no public internet exposure
- **Proxy capability:** Nexus can act as a pull-through cache for Docker Hub, preventing rate limits and keeping a copy of external images in your network
- **Multi-format:** One server handles Docker images, Maven JARs, npm, PyPI, Helm charts in separate repositories
- **Access control:** Fine-grained per-repository permissions — dev team can push to `dev` repo, only CI/CD service account can push to `prod` repo

---

## How It Works

```
Jenkins Pipeline
      │
      ▼
docker build → image: nexus:8082/sample-app:42
      │
      ▼
docker.withRegistry('http://nexus:8082', 'nexus-credentials')
      │
      │  1. Jenkins Docker plugin logs into Nexus Docker repo at port 8082
      │  2. Docker daemon pushes image layers to Nexus
      │  3. Nexus stores image in the "docker-hosted" repository
      │
      ▼
Nexus at http://localhost:8082 now has:
  └── sample-app:42
  └── sample-app:latest

      │
      ▼
ArgoCD / Kubernetes pulls from nexus:8082/sample-app:42
  └── K8s nodes must have Nexus in their allowed registries
  └── ImagePullSecret must be configured on the namespace/deployment
```

**Port split — important:**
- Port **8081**: Nexus web UI and REST API
- Port **8082**: Docker hosted repository (push/pull images here)

These are separate — the UI does not serve Docker images.

## Infrastructure Setup

### Docker Compose

```yaml
# docker-compose.yml
# Generated by GitHub Copilot
version: "3.8"

services:
  nexus:
    image: sonatype/nexus3:latest
    container_name: nexus
    ports:
      - "8081:8081"     # Nexus web UI
      - "8082:8082"     # Docker hosted repository
    volumes:
      - nexus-data:/nexus-data
    networks:
      - cicd-net

networks:
  cicd-net:
    name: cicd-net       # same network as Jenkins and SonarQube

volumes:
  nexus-data:
```

Start it:
```bash
docker compose up -d nexus
# Nexus takes 2-3 minutes to start
docker logs -f nexus   # watch until you see "Started Sonatype Nexus"
```

**Get the initial admin password:**
```bash
docker exec nexus cat /nexus-data/admin.password
```
This file is deleted after you change the admin password in the UI. Copy it before that.

## First-Time Configuration (Web UI)

Access at: `http://localhost:8081`

### Step 1 — Sign in and change password
1. Sign in: `admin` / (password from `admin.password` file)
2. Follow the setup wizard — set a new admin password
3. When asked about anonymous access: **disable** it (you want authentication required to push/pull)

### Step 2 — Create a Docker Hosted Repository
This is the repository where Jenkins pushes images.

1. **Administration** (gear icon) → **Repositories** → **Create repository**
2. Select recipe: **docker (hosted)**
3. Fill in:
   - **Name:** `docker-hosted`
   - **HTTP port:** `8082` ← this is how Docker pushes and pulls
   - **HTTPS port:** leave blank (we use HTTP for local learning)
   - **Allow anonymous docker pull:** unchecked
   - **Enable Docker V1 API:** unchecked (V2 is the current standard)
4. Click **Create repository**

### Step 3 — Create a Service Account for Jenkins
Do NOT use the admin account in Jenkins credentials. Create a dedicated user.
Plugin Required - `Role-Based Authorization Strategy`
1. **Administration** → **Security** → **Users** → **Create local user**
   - ID: `jenkins-deployer`
   - Password: strong password (this goes into Jenkins credentials)
   - Roles: **nx-anonymous** (read) + needs write to `docker-hosted`
2. To grant write access: **Administration** → **Security** → **Roles** → **Create role**
   - Role ID: `docker-push`
   - Privileges: add `nx-repository-view-docker-docker-hosted-*`
3. Assign `docker-push` role to `jenkins-deployer`

### Step 4 — Configure Docker Daemon to Trust Nexus (HTTP)

Docker refuses to push to HTTP registries by default (only HTTPS). Since you are using HTTP for learning:

On the Jenkins agent machine (and on K8s nodes that need to pull from Nexus):
```bash
# Add Nexus as an insecure registry
sudo nano /etc/docker/daemon.json
```
Add:
```json
{
  "insecure-registries": ["nexus:8082", "localhost:8082"]
}
```
Then:
```bash
sudo systemctl restart docker
```

**In production you would use HTTPS with a valid certificate.** For learning on localhost, HTTP with insecure registry is acceptable.

## The Jenkinsfile Stage

```groovy
// Generated by GitHub Copilot
stage('Push to Nexus') {
    steps {
        script {
            // docker.withRegistry handles login and logout automatically
            docker.withRegistry("http://${NEXUS_REGISTRY}", 'nexus-credentials') {
                docker.image("${IMAGE_NAME}:${IMAGE_TAG}").push()
                // Also tag as latest for convenience
                docker.image("${IMAGE_NAME}:${IMAGE_TAG}").push('latest')
            }
        }
    }
}
```

Where your `environment` block has:
```groovy
environment {
    NEXUS_REGISTRY  = 'nexus:8082'
    IMAGE_NAME      = "${NEXUS_REGISTRY}/sample-app"
    IMAGE_TAG       = "${env.BUILD_NUMBER}"
}
```

**The image name MUST include the registry prefix** to tell Docker where to push:
- Correct: `nexus:8082/sample-app:42`
- Wrong: `sample-app:42` (Docker tries to push to Docker Hub)

## Configuring K8s to Pull from Nexus

K8s nodes cannot pull from Nexus without credentials. Create an `imagePullSecret`:

```bash
kubectl create secret docker-registry nexus-pull-secret \
  --docker-server=nexus:8082 \
  --docker-username=jenkins-deployer \
  --docker-password=yourpassword \
  --docker-email=ci@company.com \
  -n your-namespace
```

Then reference it in your deployment:
```yaml
spec:
  imagePullSecrets:
    - name: nexus-pull-secret
  containers:
    - name: app
      image: nexus:8082/sample-app:42
```

Or set it as the default pull secret for a namespace:
```bash
kubectl patch serviceaccount default \
  -n your-namespace \
  -p '{"imagePullSecrets": [{"name": "nexus-pull-secret"}]}'
```

## Common Errors + Debugging

### 1. `http: server gave HTTP response to HTTPS client`
**Error:** `Error response from daemon: Get "https://nexus:8082/v2/": http: server gave HTTP response`
**Cause:** Docker is trying HTTPS but Nexus is running HTTP
**Fix:** Add `nexus:8082` to `/etc/docker/daemon.json` under `insecure-registries` and restart Docker

### 2. `unauthorized: access to the requested resource is not authorized`
**Error:** Push fails with 401 Unauthorized
**Cause 1:** Wrong username/password in Jenkins credential
**Cause 2:** The `jenkins-deployer` user does not have write permission to the `docker-hosted` repository
**Fix:** Verify credentials in Nexus UI — Administration → Security → Users → test login. Check the user's roles include write access to the docker-hosted repo.

### 3. `denied: requested access to the resource is denied`
**Error:** 403 Forbidden during push
**Cause:** User exists and credentials are correct, but the role does not include push (write) privilege
**Fix:** Administration → Security → Roles → confirm the role has `nx-repository-view-docker-docker-hosted-add` and `nx-repository-view-docker-docker-hosted-edit` privileges

### 4. Jenkins pipeline: `image name or ID not found`
**Cause:** The Docker build stage did not tag the image with the full Nexus registry prefix, so the push stage cannot find an image called `nexus:8082/sample-app:42`
**Fix:** Ensure the Docker build command uses the full image name: `docker build -t nexus:8082/sample-app:${BUILD_NUMBER} .`

### 5. K8s pod stuck in `ImagePullBackOff` after ArgoCD deploys
**Cause:** The K8s node cannot pull from Nexus (no imagePullSecret, wrong registry URL, or network route to Nexus does not exist from K8s nodes)
**Fix:** Verify the imagePullSecret exists in the namespace. Verify the image name in the deployment YAML matches exactly what is in Nexus. Check if K8s nodes can reach the Nexus host IP on port 8082.

## Break It on Purpose

**1. Push without insecure-registries configured**
Skip the `/etc/docker/daemon.json` step. Try to push from Jenkins.
Observe the exact error: `Error response from daemon: Get "https://nexus:8082/v2/": http: server gave HTTP response to HTTPS client`
Fix it: add `"insecure-registries": ["nexus:8082"]`, restart Docker, retry.

**2. Push with wrong credentials**
In Jenkins, edit the `nexus-credentials` credential — change the password to something wrong.
Run the pipeline push stage. Observe: `unauthorized: access to the requested resource is not authorized`
Fix: update the credential back to the correct password.

**3. Deploy to K8s without imagePullSecret**
Deploy a pod using the Nexus image but without the `imagePullSecrets` field in the deployment.
`kubectl get events -n default` — find the `ImagePullBackOff` event.
Read the exact error message in the event (it shows which registry was tried and what auth error occurred).
Fix: add the imagePullSecret and reapply.

## Scenario — The Complete ImagePullBackOff Diagnosis

ArgoCD syncs your deployment. Pod status shows `ImagePullBackOff`. Walk through this diagnosis in order:

```bash
# Step 1 — what is the exact error?
kubectl describe pod <pod-name> -n default
# Look at: Events section at the bottom
# The error will say one of:
#   "unauthorized" → wrong credentials or no imagePullSecret
#   "not found"    → image tag does not exist in Nexus
#   "connection refused" → K8s node cannot reach Nexus on port 8082

# Step 2 — verify the image actually exists in Nexus
curl -u jenkins-deployer:password \
  http://<nexus-ip>:8082/v2/sample-app/tags/list
# If 404 → the push stage failed silently or pushed with a different tag

# Step 3 — verify the imagePullSecret exists
kubectl get secret nexus-pull-secret -n default
kubectl get secret nexus-pull-secret -n default -o jsonpath='{.data.\.dockerconfigjson}' | base64 -d
# Verify the registry URL, username, and password are correct

# Step 4 — verify the secret is referenced in the deployment
kubectl get deployment sample-app -n default -o jsonpath='{.spec.template.spec.imagePullSecrets}'

# Step 5 — verify the K8s node can reach Nexus
kubectl run debug --image=alpine --restart=Never -- sh -c "wget -O- http://<nexus-ip>:8082/v2/"
kubectl logs debug
```

Your task: work through this full diagnosis chain on your own cluster until you can identify the root cause from just the `kubectl describe pod` output without running the remaining steps.

## Interview Questions

**Q: What is the role of Nexus in a CI/CD pipeline?**
A: Nexus is the artifact registry — Jenkins builds and scans the Docker image, then pushes it to Nexus. From there, K8s (via ArgoCD or directly) pulls the image when deploying. It is the handoff point between CI (Jenkins) and CD (ArgoCD/K8s). It also version-controls every image by build number so you can deploy or roll back to any specific version.

**Q: How does Jenkins authenticate with Nexus?**
A: Jenkins stores Nexus credentials (username/password) as a Jenkins credential. The Jenkinsfile uses `docker.withRegistry('http://nexus:8082', 'nexus-credentials')` which logs in to the registry before pushing. Jenkins never sees the raw password in the Jenkinsfile — it is injected at runtime from the credential store.

**Q: Why do you get `http: server gave HTTP response to HTTPS client` and how do you fix it?**
A: Docker defaults to HTTPS for all registries. If Nexus is running on HTTP (common for local/dev setups), the Docker daemon must be configured with `insecure-registries: ["nexus:8082"]` in `/etc/docker/daemon.json` followed by a Docker service restart. In production, Nexus should be behind a reverse proxy with a valid TLS certificate.

**Q: How do you configure Kubernetes to pull images from a private Nexus registry?**
A: Create an `imagePullSecret` with the registry URL and credentials using `kubectl create secret docker-registry`. Reference this secret in the deployment's `spec.imagePullSecrets`. Without this, the kubelet cannot authenticate with Nexus and pods fail with `ImagePullBackOff`.

**Q: What is the difference between a Docker hosted repository and a Docker proxy repository in Nexus?**
A: A hosted repository stores images you push (your own built images). A proxy repository caches images pulled from an external registry (like Docker Hub) — it acts as a pull-through cache so you avoid Docker Hub rate limits and have a local copy of external dependencies. Many companies use both: a hosted repo for internal images and a proxy repo for Docker Hub.
